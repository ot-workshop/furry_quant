# 机器学习与自动因子研究方向（方案，尚未实现）

核验日期：2026-11-12。以下是后续研发顺序，不是收益承诺；本次仅修复数据基础设施，不增加训练服务或模型依赖。

## 先区分三个方向

- 自研组合：人工定义因子与公式，再用固定权重、约束回归或历史成熟标签下的滚动 IC 权重合成评分。容易解释，应作为所有模型的基线。
- 机器学习选股：模型从已有量价、估值、财务因子预测未来可交易收益或横截面排序，输出 prediction score，复用当前交易规则与费用回测。它不必生成公式。
- 自动因子挖掘：生成表达式树，执行并评价，保存新因子与结构。神经网络、强化学习、遗传规划和 LLM 都可以作为生成器。

## 原项目核验

1. [imbue-bit/AlphaGPT](https://github.com/imbue-bit/AlphaGPT) 的 [仓库说明](https://github.com/imbue-bit/AlphaGPT/blob/main/CATREADME.md)、[生成模型](https://github.com/imbue-bit/AlphaGPT/blob/main/model_core/alphagpt.py)、[公式执行器](https://github.com/imbue-bit/AlphaGPT/blob/main/model_core/vm.py) 表明：Transformer 生成公式 token，StackVM 执行，研究结果供策略模块消费。其主链路针对 Solana 代币，含流动性、买卖压力等链上特征；执行和行情链路不能原样用于 A 股。可借鉴模型/公式生成接口，先独立复现验证，再决定适配范围。
2. [Alpha-GPT 论文](https://arxiv.org/abs/2308.00016) 是另一个同名方向，强调人类研究员与 LLM 交互式挖掘，并非上述加密项目的深度强化学习实现。
3. [AlphaGen](https://github.com/ICT-FinD-Lab/alphagen) 与 [KDD 2023 论文](https://arxiv.org/abs/2306.12964) 挖掘协同因子集合，奖励关注对组合的增量贡献，提供 Qlib 适配。对于本项目，优先把它作为可复现的 A 股公式挖掘基线。
4. [Qlib](https://github.com/microsoft/qlib) 支持监督学习、市场动态建模和强化学习；[RD-Agent](https://github.com/microsoft/RD-Agent) 可作为更后期的自动研究编排候选。先复用成熟训练与评估能力，再考虑自动化编排。

## 第一阶段：统一研究样本与实验记录

- 从当前不可变行情、成分、行业、财务版本生成统一 FeaturePanel，记录每列的公式、依赖字段、可用时间、预热跨度和缺失规则。
- LabelPanel 使用下一可交易开盘到未来指定交易开盘的收益，保留停牌、涨跌停、缺行情等可交易标识；标签完全实现后才允许进入训练或滚动 IC 统计。
- 同一天所有股票进入同一时间分段，不随机拆行。训练、验证、最终测试按时间排列；按标签实际结束日期清除跨边界样本，并设置隔离区间。
- 标准化、缺失处理、选特征、行业残差拟合及超参搜索只在训练/验证允许的范围内完成。财务时间口径固定，默认先用量价因子验证整条链路。
- 保存 dataset version、特征实现版本、训练区间、标签截止时间、参数、随机种子、环境与模型文件校验值。训练任务与现有下载/回测队列共用任务接口，训练用独立进程和资源限额。
- 当前已反复观察过的年份只能称历史滚动样本外，不能再声称从未触及的盲测；最终增加新的前向模拟区间。

验收：未来样本或财报修订不能改变过去特征/预测；同种子可重现；仅切换预测器时数据、成交规则和费用保持一致。

## 第二阶段：人工自研因子与组合

- 建立受限表达式语言：Add/Sub/Mul/Div、正向 Delay、RollingMean/Std、过去窗口相关系数、同日横截面 Rank；禁止负滞后、居中窗口和任意 Python 执行。
- 表达式存为 AST 与稳定哈希，网页展示可读公式、树结构、窗口、字段与预热需求。新增表达式走同一因子原值/评分/覆盖诊断和中性化链路。
- 组合基线依次为等权、固定自定义权重、Ridge/ElasticNet；再评估只使用成熟标签的滚动 IC/IR 动态权重，设最小样本、权重上限与收缩，避免月度噪声追涨。
- 因子库保存来源（人工、模型、自动挖掘）、训练/验证数据、版本、IC、相关性、换手和成本后贡献。表达式合法不等于因子有效。

验收：等价公式/固定权重可复现现有结果，窗口和权重确实改变评分，追加未来数据不改变旧区间，自动生成公式与手写公式使用同一个执行器。

## 第三阶段：监督学习基线

- 先接 Ridge 与 Qlib/LightGBM 回归或排序，固定同一股票池、标签、数据版本和交易成本与人工组合比较。
- 网页支持训练/验证/测试区间、标签窗口、模型参数、运行与模型版本；显示验证/测试 RankIC、ICIR、分组收益、成本后净值、回撤、换手及特征重要性。
- 使用滚动训练/预测，模型只预测其训练标签完全成熟之后的区间。一次训练不能预测其训练区间并充当样本外成绩。
- 行业/市值处理作为可控实验，所有候选共享相同成本与成交限制，报告不同市场阶段与行业暴露。

资源：当前 8 核/8GB Linux 可先小股票池、日频、CPU 模型；实际内存与耗时需测量。研究训练与 API/下载分进程，预留系统内存。

## 第四阶段：自动生成因子公式

- 先用随机/遗传搜索建立简单基线，再适配 AlphaGen 的强化学习因子池，最后比较 AlphaGPT 式 Transformer 公式生成器。
- 生成器只消费训练/验证接口，输出受限 AST；不能访问封存测试收益，也不能改回测器。所有候选统一复算并留存搜索次数。
- 奖励不只看单因子 IC：加入与现有因子池的增量贡献、相关性惩罚、公式复杂度、覆盖率、跨阶段稳定性及换手/成本惩罚。训练阶段可用快速代理评价，入库前必须跑统一完整回测。
- 设总候选数、时间、CPU/GPU和内存预算；冻结候选和参数后一次性评估最终测试，避免重复看测试集再优化。考虑多重检验和数据挖掘偏差。
- 自动生成因子先进入“候选库”，通过样本外验证后才允许加入组合；保留失败公式、重复结构和拒绝原因。
- 深度生成模型是否值得上 GPU，取决于前面基线的实际效果与耗时；届时单独评估显存/硬件，不把 GPU 作为当前重构的前提。

建议顺序：统一样本与时间验证 → 人工公式/组合基线 → LightGBM 滚动预测 → AlphaGen 自动挖掘 → AlphaGPT 生成器对照。每一步均使用同一套 A 股交易规则和净成本评估，不能凭训练奖励选策略。
