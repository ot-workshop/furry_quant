# 本轮协作审查取舍

DS通过本机Claude Code实现配置模块、数据状态页面，并对数据与回测流程提出四条审查意见。主agent逐项检查，未直接把审查输出当成事实。

| 意见 | 评估与处理 |
| --- | --- |
| 缺失或非正PE应使整个行情快照失败 | 不采用这一规则。亏损股票的非正PE是合法市场状态；行情完整性与因子可算性需要分开。实际缺失交易日会补抓或拒绝，PE缺失/非正明确展示、排除出估值因子；任一决策日缺少足够评分时回测失败，不沿用旧信号。 |
| Qlib会在评分当日开盘使用当日评分，应该再移一天 | 经核查不成立。所用Qlib的TopkDropoutStrategy在取预测窗口时调用get_step_time(trade_step, shift=1)，已有成交测试验证前一交易日评分、下一交易日开盘。再次整体平移会多延迟一日。保留显式available_at校验及反例测试。 |
| 刷新失败后普通重跑可能混用不同刷新计划 | 接受并修复。刷新使用独立缓存代次；失败不推进当前成功代次，普通下载仍用旧代次；带refresh重跑可续传待完成代次，成功才切换。增加失败刷新、普通重跑、刷新续传及旧快照保持可读的集成测试。 |
| Qlib派生文件写入不可变快照且并发写可能冲突 | 接受并修复。真实回测的派生文件移到结果目录.qlib/下，工作目录加进程文件锁；标准行情快照不再被回测写入。已验证相同目录被占用时在写特征之前明确失败。 |

另外，真实供应商验收发现按区间返回的复权因子可能漏行。系统使用实际交易日请求补抓，并对代码、日期、原始响应摘要和最终覆盖再次校验；不会用前向填充伪造完整数据。供应商历史数据及估值实际发布时间仍未独立核实，本轮不引入真实财报因子。
