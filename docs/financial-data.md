# 财务数据（Tushare 2000 积分）

财务报表为基本面因子提供输入。数据按股票增量下载、按内容寻址保存；研究统一使用公告日估计口径，提交时绑定不可变数据版本。

## 权限与范围

| 接口 | 用途 | 积分 | 调用方式 |
| --- | --- | --- | --- |
| `income` | 利润表 | 2000 | 按 `ts_code` |
| `balancesheet` | 资产负债表 | 2000 | 按 `ts_code` |
| `cashflow` | 现金流量表 | 2000 | 按 `ts_code` |

每只股票对三张表各取 `report_type` 1（最新合并报表）、4（次年公布的上年同期调整数）、5（调整前原始数），共 9 次请求。

`balancesheet` 单次最多返回 100 行，直接请求全历史会把 2010 年以前的报表截断（实测 600000.SH 只拿到 64 个报告期）。下载器在响应触顶时按 10 年窗口分页，窗口仍触顶则减半，单个年份仍触顶则报错而不是发布被裁剪的历史。实测分页后恢复到 109 个报告期（1996 年起）。

- 共享 `NetworkBudget`：官方 Tushare 每分钟 120 次、每接口每日约 9 万次。340 只股票约 26 分钟。
- `income_vip` / `balancesheet_vip` / `cashflow_vip` 需要 5000 积分，本期不使用。
- 新闻、公告文本、业绩预告、快报、分红、财报披露计划不在本期范围。

## 目录结构

```
STORAGE_ROOT/data/financials/
  objects/<内容哈希>.parquet   每只股票的观测表与交易日历（不可变）
  stocks/<ts_code>.json        当前对象指针、抓取时间、行数、最新报告期
  versions/<版本号>.json       版本清单：股票 → 对象哈希
  current.json                 最新版本
  jobs/<计划号>/               plan.json、progress.json、checkpoint.json（逐报表续传）
  PAUSE、worker.lock           暂停与运行锁
```

- 观测表保存供应商每次返回的**不同**内容；重新抓取不会覆盖历史。供应商后来删掉的行也保留。
- 对象与版本号都由内容哈希生成：数据没变时重复下载得到同一版本号，研究结果仍可复用。

## 时点规则

1. 公告日取 `f_ann_date`，缺失时取 `ann_date`；两者都缺的行被**隔离**，不进入研究，也不猜时间。
2. 财报从公告日后的**下一交易日 09:30（Asia/Shanghai）**起可用于研究。下载时间不限制普通历史财报的可用区间。供应商未留痕的历史修订可能影响结果，因此这一口径不能认定为严格 PIT。
3. 同一公告日出现不同数字时：
   - 同一首次观测日内用 `update_flag` 区分（1=最新、0=被取代）；更晚观测到的标记不能删除先前的历史观测；
   - 若没有标记，首次观测到的按公告日可用，后续视为就地更正，自**首次观测到的下一交易日**起可用。
4. 存在 `report_type=5`（调整前原始数）时：
   - 原始数按原公告日可用；
   - 被覆盖的最新值（类型 1，公告日不晚于原始数）要等次年同期调整数（类型 4）公布，或等我们首次观测到它，才可用。
5. 同一时刻出现多个版本时，优先级为 原始数 < 最新合并报表 < 次年调整数。
6. 结果标记 `point_in_time_certified=false`：供应商未留痕的历史更正无法还原。首次观测时间仍作为修订证据保存，不再作为可选的研究模式。

## 因子口径

利润表与现金流量表是**年初至今累计值**，直接跨季度比较会把一季报和年报放在同一天排序。所有流量统一换算为 TTM：

```
TTM(P) = YTD(P)                                     （P 为年末报告期）
TTM(P) = YTD(P) + 年报(上一年) − YTD(上年同期)      （其余报告期）
```

资产负债表是时点存量，分母取本期与上年同期的平均值。最新报告期距交易日超过 400 天视为过期，置空。

| 因子 | 公式 | 方向 |
| --- | --- | --- |
| `value` | TTM 归母净利润 / 当日总市值（同为元，保留负数和零） | 高 |
| `roe_ttm` | TTM 归母净利润 / 平均归母权益 | 高 |
| `roa_ttm` | TTM 归母净利润 / 平均总资产 | 高 |
| `gross_margin_ttm` | (TTM 营业收入 − TTM 营业成本) / TTM 营业收入 | 高 |
| `asset_turnover_ttm` | TTM 营业总收入 / 平均总资产 | 高 |
| `debt_to_assets` | 总负债 / 总资产 | 低 |
| `accruals_ttm` | (TTM 归母净利润 − TTM 经营现金流) / 平均总资产 | 低 |
| `profit_growth_ttm` | (TTM − 上年同期 TTM) / 上年同期 TTM | 高 |
| `revenue_growth_ttm` | TTM / 上年同期 TTM − 1（上年需为正） | 高 |

原始缺失值保持为空。盈利收益率和毛利率的真正缺失可选择记0分（默认）、记50分或剔除，填补评分不改变其他因子的权重。其他财务因子严格处理缺失。

毛利率仅使用一般工商业报表（`comp_type=1`）的 `revenue` 与 `oper_cost`，不将 `total_revenue`（营业总收入）或 `total_cogs`（营业总成本）混入。非年报TTM的三份组成报表必须都可用且同为工商业类型。营业收入须为正，已披露的零成本、零毛利和负毛利有效；缺成本不能当作零成本。其他因子的收入口径不受此规则影响。

当时已可用利润表明确为银行、保险、证券或多元金融（类型2、3、4、7）时，通用毛利率不适用，原始值为空，该项固定记50分，区别于真正缺失。报表类型无法确认或尚无报告时，仅允许使用研究提交时固定的申万历史一级行业（银行480000、非银金融490000）按信号日判定；不使用当前行业或股票名称倒推历史，历史行业尚未生效时不会提前采用。不适用项即便选择“缺失时剔除”也仍记50分；实际无任何真实因子值的股票不参与组合评分。

网页覆盖说明分别统计真实有效、不适用和缺失；个股明细展示TTM收入、成本、报表类型、组成报告期和可用时间。行业中性化先处理真实因子值，再赋予不适用及缺失评分。单因子IC、分组和相关性不使用这些赋分值。财报与行业历史修订时点仍未严格PIT认证，结果保留相应声明。

## 下载

1. 数据管理 → 行情下载：先发布一个行情版本（股票清单与交易日历来自它）。
2. 数据管理 → 财务数据：选择行情版本与更新间隔，预览待下载股票数、跳过数与预计请求数。
3. 确认下载：任务进入 worker 串行队列；可暂停、可续传。
4. 全部股票成功才发布新版本；有失败时为 `partial`，不替换当前版本。

更新间隔内的股票会被跳过；设为 0 表示立即增量更新，回看最近 400 天的**公告日期**（不是报告期）。每 90 天自动全量校订；网页“全量校订”可立即检查全部历史，发现没有新公告日期的旧报告修订。增量更新无法保证当天发现这些旧报告的就地更正。

每张报表、每种报告类型都有独立检查点；暂停或失败后只请求未完成的报表。未完成股票的中间对象只写入任务检查点，不进入已发布版本。官方交易日历复用既有年份，新年份才补充。接口达到返回条数上限时自动分窗，不能确认完整性时不发布。

## 研究绑定

- 选择基本面因子时，服务端把**当前版本**写入任务执行参数；后续下载不会影响已提交的研究。
- 财务版本、固定的公告日估计口径和特征实现版本进入因子、回测、评估和方案比较的指纹。不使用基本面因子时指纹保持不变，旧结果仍可查看。旧配置中的时间口径字段不再切换研究模式。
- 股票池在所选版本中没有任何可用财报时拒绝提交；有效覆盖不足两只时也拒绝，因为无法形成横截面。
- 方案比较的每个候选方案共享同一财务版本，即使只有部分候选使用基本面因子。

## 已知限制

- 供应商只提供公告日期，没有精确发布时间；保守按下一交易日开盘可用。
- 历史上的就地更正若既没有类型 4/5 留痕、又早于我们第一次抓取，无法还原。
- 财务数据本身不是严格 PIT 认证数据；结果与报告中均标注 `point_in_time_certified=false`。
- 400 天过期阈值适用于年报与季报混合的常规披露节奏；长期停牌或退市前的报表会被置空。
