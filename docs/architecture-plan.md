# 量化项目架构与实施规划

当前主线状态及近期顺序已于2026-11-02核对，见[主线进度与优先级](mainline-status-and-priorities.md)。下文保留原架构推演与阶段定义；滚动IC／ICIR动态权重归P5选做增强，近期暂缓。

日期：2026-11-01
状态：已支持官方主源历史仓库、动态成分因子/回测、科创板日线规则、因子诊断、历史分段比较及网页配置与任务运行；本机单队列、独立计算子进程、持久状态和结果关联已实现。动态池由已知月度快照次日生效，预热/排名/退出分离，明细列式存储与按需读取，完整规则边界见[动态研究实现](historical-index-research.md)。正式市场数据库、精确成分公告认证、财报版本验收和网页历史分段实验配置待建设。下文保留原架构推演，PostgreSQL等为规划而非已实现。

架构决策：Qlib 作为首个研究与回测后端，复用其策略基类、执行器、交易所、账户和评估能力。本项目负责供应商接入、标准数据、历史可见时点、因子定义、业务约束、实验编排和结果留存；不自研通用回测引擎、撮合器或账户账本。下面的交易与账户条款是后端验收要求，不代表需要自行重建实现。

## 1. 目标与范围

建立可复现、可扩展的个人量化研究系统，贯通数据更新、因子研究、策略组合、日线回测和结果分析。

第一版按A股、日线、单账户、只做多、不融资规划。当前已联合核验五股、424个交易日行情及388个交易日的Qlib回测；四股价格与复权使用BaoStock整段回退，茅台保留Tushare。原Tushare单源跨年异常候选仍被隔离，当前联合案例独立发布。新增历史分段方案比较复用Qlib，各段独立开户、仅按验证期选方案；这批数据此前已用于研究，不能称为全新未见样本。仍需逐步迁移旧项目能力。

第一版包含用于个人本机访问的网页配置、任务运行和结果展示：股票池/因子/窗口/权重、回测参数、股票评分和净值等。队列和任务状态保存于SQLite，Qlib在独立子进程中串行运行。第一版不包含实盘下单、分钟与逐笔撮合、分布式任务、微服务、通用插件平台、机器学习训练平台。

成功标准：给定明确版本的数据、配置和策略，能够重复得到相同的订单、成交、账户快照和净值；每笔收益变化可追溯。

## 2. 总体结构

采用前后端分离和模块化单体后端：前端负责查询与展示，Python 后端负责数据、研究与 Qlib 调用。前后端分离不等于拆成微服务。

```text
浏览器前端 --> HTTP API --> 提交本机研究任务 / 查询已保存结果
                              |
CLI / Python 调用 ------------+
        |
应用服务：更新数据、计算因子、运行回测、生成目标组合
        |
        +-- 研究计算 --> 策略信号 --> 组合构建与约束
        |                                  |
        +-------------------------- Qlib 回测适配
                                           |
                               Qlib 执行器/交易所/账户
                                           |
                                      结果与报告

研究 --> 统一的历史数据读取接口
                                ^
                         PostgreSQL 读取实现
                                ^
                     标准化、质量检查、入库
                                ^
                     Tushare 采集 + 原始文件

标准数据快照 --> Qlib 数据导出 --> Qlib 数据提供器 --> Qlib 回测
```

数据更新与研究回测是两个独立流程。回测缺数据时明确失败或输出不完整状态，不在计算途中自动联网补数据。

首期网页只读取后端已保存结果，任务通过 CLI 执行。增加管理功能后，API 仅提交任务并返回任务 ID，由独立计算进程运行 Qlib，页面查询状态；关闭页面不影响计算。长耗时回测不得放在网页请求生命周期内执行。

## 3. 模块职责与边界

| 模块 | 负责 | 约束 |
| --- | --- | --- |
| domain | 标的标识、时间约定、数据快照、评分与目标组合等业务契约 | 不重复定义完整交易引擎模型 |
| data | 数据契约、采集、标准化、质量检查、存储、历史数据读取 | 原始供应商字段只在适配器内解释 |
| research | 原始因子、去极值、标准化、中性化、收益标签、因子评估 | 计算函数不访问网络和数据库 |
| strategies | 接入 Qlib 策略基类，使用合法时点的评分或目标组合 | 不执行 SQL，不修改账户，不自行撮合 |
| portfolio | 信号转目标权重、缓冲规则、集中度与仓位约束 | 约束冲突明确报告，不默默放松限制 |
| integrations/qlib | Qlib 数据导出、策略桥接、回测配置、调用及结果转换 | 复用后端时钟、订单、撮合和账户，避免复制实现 |
| reporting | 绩效、归因、图表和可读报告 | 基于标准结果计算，不反向修改交易过程 |
| application | 组装依赖、执行任务、保存运行记录 | 示例脚本不承载独立业务逻辑 |
| api | 查询与分页、参数验证、任务提交和产物访问 | 复用应用服务，不直接承载回测计算，不返回供应商密钥 |
| frontend | 股票、因子和回测页面，后期提供配置及任务状态交互 | 只消费公开 API，不访问数据库或供应商，不重新实现因子和绩效公式 |

只在实际变化点引入接口：采集、历史数据读取和研究输入输出。后端先只实现 Qlib，不预先建设多引擎插件平台。策略与交易配置优先使用 Qlib 原生扩展点，只有验收确认存在缺口时才增加最小扩展；不以扩展为名重建完整撮合器。计算函数优先使用普通函数和明确参数。

行情、财报和因子采用批量 DataFrame 加字段契约；配置和运行清单采用有类型的模型。订单、成交和持仓首先使用 Qlib 原生结构，必要时仅在结果出口转换。

## 4. 统一数据契约

### 4.1 标识、单位与时间

- 标的标识由市场、交易所、代码组成；保留供应商代码映射，不让 BaoStock 或 Tushare 编码成为业务逻辑。
- 日期内部使用日期类型；带时刻的数据使用有时区的时间。日线业务日按 Asia/Shanghai 解释。
- 标准层明确价格币种、成交量单位、成交额单位、股本单位、百分数与小数比例；适配器负责转换并校验。
- 行情明确区分交易日期、数据可用时间、采集时间；财报区分报告期、公告日期和版本。
- 每个数据集定义主键、必需列、可空列、排序规则和重复处理方式。

### 4.2 价格与公司行动

- 保存未复权行情和复权因子；研究价格派生时记录复权方法和基准日。
- Qlib 使用其价格、成交量与还原因子的约定；导出时显式转换。Qlib 的还原因子不能未经核对直接等同于供应商的累计复权因子。
- 标准层保留未复权价格和公司行动来源，后端模拟采用何种复权与分红处理需通过对照样本确认并记录。不能在复权收益之外重复计入公司行动收益。
- 早期框架验收先使用无公司行动的受控样本，随后增加送转、分红的对照样本。未验证前不得宣称支持逐笔现金分红账本；若 Qlib 处理口径不同，明确限制并决定是否接受。
- 停牌、缺失、未上市和退市是不同状态；缺失行情不能统一填零收益。

### 4.3 截至时点可见的数据

- 研究查询必须指定 `as_of`，只返回截至该时点可见的数据。
- 策略侧只能使用已按可见时点生成并正确对齐的评分或目标组合；Qlib 能加载完整历史数据不等于自动保证无未来信息，需要在数据准备与策略适配边界验证。
- 历史股票池和行业使用有效区间；不拿当前成分替代历史成分。
- 财报修订保留版本与可用时间；如果供应商只提供最新修订值，需记录局限，不能宣称严格复现当时信息。
- 收益标签属于评估数据，与策略特征隔离；用于动态权重学习的标签必须在决策时点前完全结束。

## 5. 数据层设计

### 5.1 第一版存储选择

沿用已有 PostgreSQL 使用基础，保存标准数据、任务状态和数据版本记录。原始返回数据以 Parquet 文件留存，同时保存请求元数据；报告和运行产物存放在独立目录。

当前阶段采用原始Parquet缓存、不可变标准快照和JSON运行记录，并以SQLite保存本地下载任务及快照索引；已支持可配置股票池和日期。PostgreSQL市场数据库尚未实现，后续按正式数据规模建设。详见[数据管理](data-management.md)。

首条验证流程直接从受控样本生成 Qlib 所需数据，无需先建设数据库。真实数据阶段再实现 PostgreSQL 标准存储，并通过冻结快照导出 Qlib 数据，不在回测过程中逐次查询 PostgreSQL。数据库表结构由显式迁移管理。

### 5.2 数据分层

1. 原始层：供应商返回字段、采集时间、接口、脱敏请求参数、批次和文件摘要。
2. 标准层：统一字段、单位和时点规则，完成质量检查后入库。
3. 研究层：派生价格、因子、标签等可重建结果，记录来源与计算参数。

数据版本必须对应可恢复的文件或记录集合，不能只记录一个会继续变化的数据库最大日期。初期通过不可变采集批次与运行所用标准数据导出实现复现，不要求立刻建设完整数据版本平台。

### 5.3 采集任务

- 任务按数据集与日期/标的分区，记录 pending、running、success、partial、failed 状态。
- 保存成功覆盖范围、预期范围、行数和校验结果；只在数据完成校验并提交后推进进度。
- 分页、截断检测、限流、退避重试、失败补抓和幂等写入统一处理。
- 接口权限错误与临时网络故障分开处理；空响应不能自动判定成功。
- 财务等会修订的数据定期回补窗口，不能只按最大日期追加。
- 质量规则分 warning、reject；不合格数据保留原始记录，拒绝进入可回测数据集并输出原因。

### 5.4 Tushare 适配器

首个供应商为用户提供的第三方Tushare SDK兼容服务。基础接口已经实测，但历史复权存在漏行和尺度异常，多年数据未通过质量验收，不能直接套用官方积分权益。当前有效窗口和失败证据见[接入记录](real-data-status.md)。

- Token 从本地环境读取；接口地址可配置。任何源码、测试快照、运行清单和日志均不保存 Token。
- SDK 私有地址字段的兼容处理集中封装，避免散落在业务模块中。
- 先验收基础资料、日线、复权、估值、财务、指数历史成分、停复牌、涨跌停和公司行动等能力。
- 验收覆盖字段、单位、历史范围、返回上限、日期边界、重复、修订及错误响应。
- 依照数据源能力调整第一版数据范围；不可用的数据不得以编造值替代。
- 用户所述有效期为 90 天，起止日期尚未确认；优先在有效期内完成必要历史数据的可恢复归档。

## 6. 研究与策略流程

```text
可见数据快照
    -> 原始因子
    -> 去极值/标准化/中性化
    -> 评分或策略信号
    -> 目标组合
    -> 组合约束校验
```

因子定义包括名称、所需数据、回看窗口、参数、版本和计算函数。因子计算、横截面处理和因子权重模型独立，固定权重先实现，IC/IR 动态权重后实现。

缓存键包含数据版本、时点、股票池、因子版本、处理流程和全部参数；缓存结果同时保存实际使用的权重等元数据。第一条流程可先不启用缓存，正确性确认后再加入。

策略运行与目标组合生成共用同一服务，后续模拟交易也复用该服务。目标组合不能直接覆盖实际账户持仓。

## 7. 回测与账户

### 7.1 日线执行顺序

默认时序：T 日收盘后使用截至该时点可见的数据生成信号，安排下一交易日开盘执行；不能用 T 日收盘信息在同一收盘价成交。

使用 Qlib 执行器推进交易日，以下顺序和行为需用验收样本核对；若不能满足，先输出差异再决定配置或扩展：

1. 按生效时间处理公司行动及可卖数量等账户状态。
2. 用当时可用价格与账户状态生成可执行订单；默认先卖后买。
3. 根据交易状态、可用现金、数量限制、费用和成交模型撮合。
4. 用成交记录更新现金、股数、成本和费用，保留未成交及拒单原因。
5. 按收盘价估值，保存账户快照，再运行收盘策略。

具体市场规则按标的类型和日期配置，避免写成永不变化的全市场常量。日线不能重建盘中排队；涉及涨跌停等情况采用明确、保守且可配置的成交假设，并在结果中披露。

### 7.2 核心原则

- 目标权重、订单、成交和真实持仓独立。
- 持有期间股数保持不变，权重随价格漂移；仅在明确调仓时交易。
- 交易费用在成交时记账，初始建仓费用也计入；期末默认按市值计价，强制清仓作为显式选项。
- 现金、总资产、持仓市值和累计费用能够对账；不允许负现金或超卖。
- 无法满足目标组合时允许留现金，或按配置终止；不得自动突破硬性约束。
- 数据不足、计算失败与正常空仓区分；默认失败即终止，不隐式沿用旧组合。
- 结果保留期初初始资产，绩效指标保存数值，百分比格式只在展示层处理。

## 8. 实验与结果

每次运行保存独立 run_id，以及配置、策略版本、代码版本或代码快照摘要、数据版本、依赖版本、随机种子（如使用）、时序及撮合假设。

产物包含信号、目标组合、订单、成交、每日持仓与现金、净值、费用、失败原因和数值绩效指标。报告层再生成图表与可读摘要。

第一版优先总收益、年化收益、波动、最大回撤、换手、费用和基准比较。无风险收益与年化口径显式配置。不同运行仅在数据与规则口径可比时进行比较。

## 10. 实施阶段与验收

| 阶段 | 交付物 | 验收条件 |
| --- | --- | --- |
| P0：架构规划 | 本文、第一版范围和依赖边界 | 能明确每项旧功能归属及首条流程 |
| P1：Qlib 可行性验证 | 隔离环境、依赖锁定、受控行情和评分、Qlib 最小回测 | Windows 环境可运行；无需供应商和数据库；检查交易时点、现金、费用、持仓及结果可导出 |
| P2：项目骨架与适配 | 标准数据契约、Qlib 导出、策略桥接、运行配置、结果留存 | 完整样本可重复；未来数据不可见；核对权重漂移、停牌、涨跌停、费用及公司行动口径；记录未支持项 |
| P3：真实数据接入 | Tushare 验收、采集任务、原始归档、PostgreSQL、迁移与版本 | 接口能力清单明确；失败重跑不重复；缺口可追踪；真实小区间可经统一接口回测 |
| P3a：结果展示前端 | 只读 API、股票因子页、排名页、回测列表与详情 | 先用 P2 的明确标识样本结果联调，真实结果接入后无需改页面；切换日期与运行不会混用数据 |
| P4：旧能力迁移 | 审核后的因子、处理流程、多因子组合、报告 | 每个迁移函数有口径检查；财报及标签无越界读取；回测与目标组合生成共用逻辑 |
| P4a：管理功能 | 参数表单、任务队列、独立计算进程、任务状态与历史 | 提交即返回任务 ID；刷新不重复提交；关页不停任务；失败有原因；重启后中断任务状态可识别 |
| P5：研究增强 | 因子分组与 IC、滚动样本外评估、参数实验、缓存 | 动态学习只使用已完成标签；实验可复现；缓存随数据及参数变化失效 |

第三方接口可在 P1/P2 期间做少量独立验收，以及时暴露数据可得性问题；业务实现顺序仍以核心契约和样本流程为先。

P3a 的页面契约和设计随 P2 一起确定，使用已导出的样本结果开发。股票因子页以真实因子产物为前提，旧因子迁移前使用明确标注的样本数据，不将虚构评分呈现为真实研究结果。完成 P4 后交付覆盖真实因子和回测的第一版网页。

不以全市场大规模下载或漂亮收益曲线作为早期验收。优先证明时间、现金、持仓和数据版本正确。

## 14. 前后端产品与接口规划

### 14.1 技术方向与部署

- 后端拟采用 FastAPI，保持现有 Python/Qlib 业务代码；前端拟采用 React、TypeScript 和 ECharts，UI 组件优先采用现成组件库，具体版本在实施时锁定。
- 前端和后端同仓库、独立目录。开发期可分别启动；本机交付优先同源访问，降低运行负担。
- 首期默认只绑定本机。对外访问、多用户权限和部署由后续需求明确后设计；前端不存储或接收数据供应商 Token。
- 后端长任务使用独立计算进程。进入管理阶段时选用经过 Windows 兼容性验证的成熟任务队列，不自研通用调度平台；限制初始并发并隔离各次 Qlib 数据路径、配置与产物。
- API 仅接受已登记因子、策略及其合法参数，不通过网页提交任意 Python 代码执行。

### 14.2 第一版页面

| 页面 | 主要内容 | 关键交互 |
| --- | --- | --- |
| 股票详情 | 基本资料、选定日期的各因子原始值/处理后评分、综合分、排名、历史评分变化 | 搜索代码或名称；选择日期、评分方案和对比股票 |
| 因子排名 | 指定股票池、日期与评分方案下的股票列表和各因子分值 | 分页、排序、行业筛选；查看单只股票 |
| 回测列表 | 策略、区间、状态、创建时间、核心指标 | 按策略筛选；进入详情；选择可比运行 |
| 回测详情 | 净值及基准、超额收益、回撤、费用、换手、持仓变化、后端可提供的成交记录与参数 | 时间缩放、按日期查看持仓、下载结果 |

概览页面可在以上页面可用后增加，展示最近任务与数据覆盖，不作为首期阻塞项。没有结果时展示空状态和生成入口说明，不在访问页面时自动启动回测。

### 14.3 因子分数必须可解释

- 区分原始因子值、标准化/中性化后的值、排序百分位、综合分和最终组合权重；不能统一含糊标成“评分”。
- 展示得分方向，例如高分代表更符合当前因子的选股偏好，不能把高分解释成上涨概率或买入建议。
- 分数记录并展示有效日期、可见时点、股票池、横截面样本数、处理方法、因子版本、权重和数据版本。
- 对外展示可采用 0–100 排序百分位，但必须明确只是百分位。不同股票池或不同处理方案的分数不直接混合比较。
- 界面行业筛选默认只过滤已计算排名，不隐式改变归一化样本或重新评分。改变评分股票池需显式创建新评分任务。
- 财报缺失、数据过期、因子不可算等显示缺失及原因，不将空值转成 0 分。
- 评分历史必须标明计算方案；方案变更后不伪装成同口径连续时间序列。

### 14.4 后端结果与 API

评分批次和回测运行分别拥有不可变 ID。页面链接绑定具体批次/运行，避免新任务完成后旧页面内容悄悄变化。

首期查询接口草案：

| 接口 | 用途 |
| --- | --- |
| GET /api/v1/instruments | 证券搜索，返回标准标识 |
| GET /api/v1/factor-runs | 查询可用评分批次、日期、股票池与方案 |
| GET /api/v1/factor-runs/{id}/scores | 分页评分与排名，支持标的及行业过滤 |
| GET /api/v1/instruments/{id}/factor-history | 按明确方案查询历史分数与来源批次 |
| GET /api/v1/backtests | 回测记录列表 |
| GET /api/v1/backtests/{id} | 配置、数据版本、指标、执行假设及已知限制 |
| GET /api/v1/backtests/{id}/equity | 净值、基准及对应时间轴 |
| GET /api/v1/backtests/{id}/positions | 分页查询指定日期的持仓 |
| GET /api/v1/backtests/{id}/trades | 查询后端实际可提供的成交明细 |

列表在后端执行分页、排序与过滤；大图支持明确的下采样，下载保留原始精度。数值指标由后端计算并返回口径、单位；JSON 中缺失用 null，前端负责格式化。图表展示归一化的共同起点，指标计算使用全量结果。

运行产物只通过已登记 ID 获取，不接受前端传入任意本地文件路径。结果发布在全部关键产物提交后进行，部分失败或进行中不得标记为完整结果。

### 14.5 第二阶段管理交互

增加因子登记与参数说明、回测表单、因子计算/回测提交、任务状态、失败详情、历史配置复用和结果比较。优先支持参数化已有因子与策略，暂不提供在线编写代码。

提交返回 202 与任务 ID；使用幂等提交标识防止双击或刷新产生重复任务。状态至少区分 queued、running、succeeded、failed、interrupted。页面先轮询即可，不要求首期实现 WebSocket。

任务状态记录持久化，计算过程记录心跳和阶段；进程退出后通过状态检查标记中断，不承诺自动恢复未完成计算。进度优先展示明确阶段，只有已知总工作量时才展示百分比。

前后端验收以具体场景为准：选股票和日期能解释每个分值；切换方案不会串数据；打开回测能追溯参数和持仓；下载与页面一致；后续提交任务后关闭页面再打开仍能查看状态与结果。
