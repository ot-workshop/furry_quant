# 共享行情与增量更新

沪深300、自选股和全市场范围共享同一套股票日行情事实。股票池决定研究资格，不复制相同股票和日期的行情。

## 网页操作

进入“数据管理 → 共享行情与增量更新”：

1. 选择沪深300历史成分、沪深A股全市场或自选范围。
2. 设置研究日期和预热交易日；小范围验证可限定代码。
3. 预览可复用覆盖、缺口、参考数据和预计请求。
4. 确认后创建串行下载任务。
5. 从任务详情查看新增、复用、来源证据和待复核原因。

限定代码的计划只代表子集，不能标记为完整沪深300或全市场。成功任务发布独立版本；失败任务不会替换上一成功版本。

## 数据组织

PostgreSQL 保存证券生命周期、交易日历、行情、复权、估值、交易状态、历史成分、行业、基准、来源和修订。`STORAGE_ROOT` 保存供应商响应、不可变数据集和大型研究文件。

覆盖按来源、股票、日期和字段计算，不按股票池标签计算。相同股票和日期可以被不同研究范围复用；历史成分资格、行业和预热资格在研究视图中单独计算。

研究启动时将所用数据登记为内容寻址数据集。仍在增长的历史仓会根据 manifest 固化为不可变版本，旧回测不会跟随当前数据指针变化。

## 增量更新

- 新日期只下载尚未覆盖的分区。
- 跨年缺口按年度切片，便于续传和重试。
- 增量边界会重取少量相邻日期，检查 OHLC 和复权尺度连续性。
- 近期交易日可以重新核验；历史更正以显式修订记录发布。
- 空响应不表示删除，停牌、未上市、退市、未发布和接口异常分别记录。
- 边界或来源冲突会隔离候选数据，不覆盖已发布版本。

官方 Tushare 是主源。BaoStock 只串行用于抽样核验和异常补缺，不要求每只股票双源一致。单源检查、双源核验和补缺是不同证据等级。

## 股票生命周期与成分

全市场范围根据证券主数据选择区间内相关股票，包含区间内退市标的，不用当前上市名单回填历史。上市前和退市后的日期不制造行情。

沪深300使用保存的历史快照。月度快照按策略声明的下一交易日生效约定使用；未完成月份只能沿用此前已知名单，不能提前使用未来月末名单。快照观察日期不等同于公告首次公开时间，因此相关结果会保存 `point_in_time_certified=false`。

## 暂停与续传

下载在分区边界响应暂停。已完成分区保留，续传根据任务计划和校验和跳过已完成内容。同一部署只运行一个共享更新消费者，避免供应商配额和文件发布相互冲突。

全市场下载量可能很大。应先用短区间和限定股票验证，再扩展范围，并持续观察磁盘、Tushare 配额和数据质量报告。
