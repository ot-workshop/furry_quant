# 下载模式预热校验与失败任务恢复

## 默认自动推算与确认下载（2026-11-01）

新下载任务默认勾选“按回测日期与因子窗口自动计算下载区间”。用户只需选择回测起止日期、股票池与因子。点击“预览下载方案”查询并缓存交易日历，程序倒数所需历史交易日，展示预热起止、实际回测区间和完整下载区间；确认后才创建行情下载任务。既有手动日期方案继续保留。

当前15股十因子、回测2024-01-03至2026-09-30的真实日历结果：预热2023-06-29至2024-01-02，共127个交易日；完整行情区间2023-06-29至2026-09-30。预热日不进入回测收益，因子窗口与权重不会被自动改小。算法只使用回测前的历史，不会用未来行情补足开头。

确认绑定整个草稿，修改股票池、日期、因子窗口、权重、资金或交易费用都会失效；异步返回的旧方案不会覆盖新配置。日期方案接口只接收回测日期和因子即可（`auto_range: true`），不需要预先知道数据起止。自动数据结束取回测结束前的最近交易日；回测开始遇休市顺延并在确认中显示。

实际React页面连接真实本地API验证了2股、15股预览与确认，确认前没有创建任务；真实交易日历来自已配置服务。对应队列暂停，避免为界面验收再次下载多年行情。另有2股、7股、15股生成数据覆盖自动规划、稀疏复权、BaoStock断线一次重连及原生Qlib回测、因子评估；生成数据不作为行情真实性证据。见 `.agent-work/automatic-download-live-latest.json` 和 `tests/test_calendar_plans.py`。

本次全量后端452项、前端34项测试及生产构建通过。既有手动方案、缺口/重复日历拒绝、休市起止调整、不同窗口的精确历史计数以及任务结果引用检查仍保留。

2. 点“改用已有快照（免下载）”。相同股票池与范围优先选择下载目录当前发布版本；本次为 `joint-3781e34842587eae`。股票池、因子、窗口和权重保留。

## 校验与缓存规则

- 快照模式和实际准备阶段共用后端预热校验；下载请求也在进入队列之前检查。
- 下载模式可复用其他已验证股票池的共同交易日历，只计算请求数据起点至回测起点前的交易日。不会借用请求起点之前的缓存行情来假装预热足够。
- 没有覆盖区间的本地日历时，仅用自然日数作为历史交易日数上界，拒绝明显不可能的配置；不猜测具体交易日。其他配置仍在下载后按真实日历验证。
- 网页随窗口和因子变化显示所需历史、可用历史及已知最早起点，调整起点由按钮明确触发。窗口长度满足后，估值缺失、停牌、成交活跃度及负收益样本仍按既有规则检查。
- 下载完成但后续失败时，刷新可用快照列表并保留当前草稿；缓存列表刷新期间暂停复用操作，避免使用过期选择。匹配时优先相同股票池及当前下载版本，排除不同区间、基准或核验模式。
