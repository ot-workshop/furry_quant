# 沪深300历史动态股票池研究与科创板日线执行

本阶段将历史仓库接入网页、因子计算、Qlib回测和因子评估。旧固定池入口及历史结果继续保留。历史仓库的493只相关并集不会作为每天固定选股池。

## 网页流程

“新建研究”选择“沪深300历史成分股”，设置回测区间、因子/窗口/权重、持股数、每次替换数量和费用后提交。历史模式自动引用已完成仓库及其物理清单校验和，不接受客户端指定目录或手工替换成分代码，不受固定池50股限制。目标持股最多300只。

后台依次执行准备数据、因子、Qlib回测和因子评估四阶段。结果按钮引用该任务的独立批次；最后一个评分日期是回测末日前一个交易日，避免打开一个没有信号的日期。仅改资金/费用可复用评分，修改因子/日期或数据版本生成独立批次。普通固定池仍按原边界运行；科创板支持在本阶段历史池模式内启用。

## 成分时点与预热

- 采用现有月度快照“快照后下一交易日生效”口径。T收盘评分只能使用快照日期不晚于T、将于T+1执行时适用的名单，T+1开盘执行。不会用下一月份的名单回填本月。
- 该数据不能证明实际公告发布时间和每次真实调整生效日，继续标记`point_in_time_certified=false`，可能滞后真实指数调仓。程序因果性测试不能消除供应商修订或公告时点未知。
- 每股原始指标可使用调入前历史；横截面排名仅包含当时已知成分、生命周期内、预热充分且所选因子全部有效的股票。调入前历史不提前获得排名。
- 预热按交易所日历倒推最长lookback+1个已知交易日，先检查仓库覆盖；每只新股还须具有足够自身历史，不造上市前价格。中期动量126/21在2020起点使用2019-06-28起127日历史。
- 停牌、缺失因子和上市历史不足分别保留原因。候选不足不凑满持仓、不沿用旧评分，可保留已有合规持仓与现金，并保存交易处理事件。

## 调出和生命周期

调出股票即使`n_drop=0`也进入退出队列。策略只生成Qlib原生订单，成交、费用和账户更新仍由Qlib完成。停牌、开盘跌停或T+1限制阻止卖出时保留持仓，按已知价格估值，下一交易日再次检查；受阻退出占用持仓名额，不额外买入造成无意超配。

不会根据未来的“最后报价日”提前卖出。若生命周期结束后仍未能退出，禁止交易并按最后可得价冻结账户估值，保留未退出队列和警示；未实现退市清算、强制回收估值或自动按零回收。此时收益不代表可兑现现金。

回测页面新增“动态池交易处理记录”，显示成分调出、评分轮换、受阻原因和期末待退出数量；已提交与实际成交分开，成交明细仍是最终依据。

## 日线交易规则

| 规则 | 实现 |
| --- | --- |
| 主板买入数量 | 100股整数倍；单笔最多100万股 |
| 创业板买入数量 | 100股整数倍；2020-08-24起限价单笔最多30万股，此前100万股 |
| 科创板买入数量 | 最低200股，其上以1股递增；限价单笔最多10万股 |
| 余股退出 | 整仓卖出允许不足通常申报单位的余额，仍受单笔上限及可卖状态约束 |
| T+1 | 当日买入不能当日卖出，由交易所适配层及策略持仓天数双重检查 |
| 涨跌停 | 优先使用当日官方涨跌停价，不根据当前ST名称倒推历史；开盘触及买入涨停/卖出跌停时保守不成交 |
| 新股无涨跌幅限制 | 科创板前5交易日；注册制创业板及2023-04-10起主板新股前5交易日，依据上市日期和完整日历计算 |
| 已审核特殊不限幅日 | 使用仓库精确日期事件标记，保留真实涨跌；未知限制价不能直接当成无限制 |
| 全天停牌 | 零成交、禁止买卖，已知前收估值；盘中停牌不自动变成全天停牌 |

规则依据：[上交所科创板投教](https://edu.sse.com.cn/tib/qa/c/4761956.shtml)、[上交所申报上限](https://www.sse.com.cn/disclosure/diclosure/upper/index.shtml)、[深交所创业板数量规则](https://investor.szse.cn/knowledge/t20200819_580804.html)、[深交所主板规则](https://investor.szse.cn/knowledge/t20230308_599142.html)。

本模型是日线开盘成交假设，不是完整交易所撮合：不能重建盘中临时停牌时刻、申报价格笼子、队列或市场冲击。现支持[周/月调仓及分项费用](rebalance-and-costs.md)，包括可配置佣金、历史或固定税费与成交额比例冲击扣费，仍不等同于券商实际成交/账单。价格/数量继续遵循Qlib复权收益及等效持股口径，现金分红不另记现金，未新增券商逐笔分红账本。

## 大结果存储与读取

多年全池评分不再全部放进一个巨大JSON。动态因子的`history.parquet`和`diagnostics.parquet`保存完整明细，JSON保存元数据、行数及校验和；网页按日期/股票查询，列表无需反序列化全部历史。收益标签也保存独立Parquet明细，评估页提供完整下载及分页API。旧JSON产物仍兼容。

所有明细文件校验和验证后才能读取，采用临时文件及原子发布；重跑不覆盖旧产物。因子逐日生成、按批写盘，回测只读评分列，评估才读原始值，避免同时持有全部评分字典；交易状态采用按股列式查找。结果JSON采用流式写入，避免多年数据字符串复制导致内存峰值。

多年十因子评估进一步改为分批将原值转换成数值列、按持有期流式保存标签、按必要列计算IC并逐日计算因子相关性；不同时累计全部原值字典与多组标签。原配置恢复与内存上限验证见[评估内存与诊断修复](long-evaluation-memory.md)。

主要新增接口：

- `GET /api/v1/backtests/{id}/execution-events`：交易处理事件分页。
- `GET /api/v1/factor-runs/{id}/tables/history`：完整评分Parquet。
- `GET /api/v1/factor-runs/{id}/tables/diagnostics`：排除原因Parquet（存在时）。
- `GET /api/v1/evaluations/{id}/labels/{horizon}`：收益标签分页。
- `GET /api/v1/evaluations/{id}/labels/{horizon}/download`：完整标签Parquet。
