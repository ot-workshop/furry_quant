# 多股票池完整流程复核

日期：2026-10-31。此记录区分真实供应商数据与可控生成数据，不把固定五股快照或接口存活当作完整换池验收。

## 本次发现及处理

| 场景 | 原问题 | 当前行为 |
| --- | --- | --- |
| 停牌仅缺复权因子或涨跌停价 | 只有日线/日估值缺日才触发停牌预检，可能错误补抓辅助接口 | 四类行情接口任一缺日均先独立核对停牌状态 |
| 某个年度分片整个区间停牌 | 空表在获得独立交易状态证据之前就失败 | 联合模式保留空捕获，后续必须证明每个缺日为停牌并有此前报价；未知缺数仍拒绝发布 |
| 扩容或重组股票池 | 新任务只从主数据目录复用分片，已有下载任务里的共用股票会重复下载 | 从服务端控制的历史下载目录按完整请求键、供应商、缓存代次与原始文件哈希复用；损坏的无关目录索引不会阻断新池 |
| 换到尚未适配的证券类型 | 网页可接受代码，但BaoStock范围或100股交易规则不匹配，可能晚失败或得到不适用结果 | 网页、任务校验及CLI真实回测明确拒绝科创板、北交所、B股、ETF和作为股票输入的指数；目前支持沪深主板和创业板A股 |
| 数据区间包含上市前或退市后日期 | 作为普通缺日补抓，提示笼统 | 服务提供上市/退市日期时，先报告具体股票和受影响日期，要求调整数据区间，不填造上市前行情 |
| 涨跌停价等质量检查失败 | 无原始请求错误时可能只给通用失败提示 | 从质量报告提取具体股票、日期与分类；股票资料空响应也单独说明 |
| 某一候选快照不可读 | 文件存在性检查在异常处理之外，可能让整个快照列表报错 | 跳过该候选，其余已验证快照仍可使用 |

停牌证据仍要求BaoStock未复权、后复权两份记录的交易状态一致，成交活动为空或零；非数值的异常成交字段不能被当作零。停牌估值只沿用此前数据，独立来源冲突、无法确认的缺数以及没有历史报价的区间首日停牌仍失败。

## 可控故障与规模回归

`tests/test_pool_workflow_matrix.py` 生成不同代码、不同价格轨迹的2/7/17/50股池，完整走下载、任务工作流、因子与原生Qlib，独立用标量窗口及平均并列排名核对三组日期。这里的行情均为生成测试数据，不是50只股票已完成在线验证。

另覆盖多父池缓存合并、无关损坏目录索引、上市/退市日期边界、盈利收益率导致有效评分不足、改成纯价格因子后恢复、特殊证券提交前拒绝、不可读快照隔离、只缺辅助字段的停牌和整段空表停牌。旧有测试继续检查错代码、重复/越界记录、网络失败续传、未确认缺数、两源价格冲突、缓存校验、预热与未来数据边界。

最终全量369项Python测试、15项前端测试及生产构建通过。在线验收并行时曾有一次后台子进程回归失败；单项复测及在线验收结束后的整套回归均通过。失败日志保存在 `.agent-work/pool-full-tests.log`，最终通过日志为 `.agent-work/pool-full-tests-final.log`，不将未复现失败解释为已定位根因。

## 复现

```powershell
.\.venv\Scripts\python.exe -m pytest -q
npm.cmd --prefix frontend test
npm.cmd --prefix frontend run build
```

离线独立复算本机验收产物：

```powershell
.\.venv\Scripts\python.exe scripts\check_research_workflow.py --config configs\research.joint.json --runs-dir .agent-work\pool-audit\runs --evidence .agent-work\pool-audit\evidence.json --independent-pools
```

需要重新进行在线验收时，用CLI在单独端口启动隔离服务，然后将任意同格式案例JSON传给 `frontend/scripts/pool-live-e2e.mjs --base http://127.0.0.1:端口 --cases 案例.json --output 证据.json`。该命令会实际请求数据供应商并创建任务；常规单元测试不联网。

本次不是全市场或所有供应商状态的认证；科创板/北交所等数据及交易规则、退市交易处理、盘中停牌、历史成分、财报实际可得时间和大规模下载性能仍未实现或验收。
