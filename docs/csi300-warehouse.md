# 沪深300历史数据仓与限频下载

常见异常会按正式规则自动处理，并自动保存中文处理报告；网页可查看每只股票的处理原因、日期与依据，见[自动处理与报告](automatic-download-handling.md)。无法确认的新异常仍会隔离并说明，不自动编造数据。

最新下载规则改为官方主源自检、约10%固定抽样及异常核验/补缺；不再强制全股双源核验。网页及资产区分单源、双源和补缺通过，详见[当前规则](official-primary-warehouse-policy.md)。下文全股双源要求及五股隔离描述为此前阶段记录，以当前规则为准。

启用及完成日期：2026-11-01。493/493只已完成捕获及检查，440只单源检查通过、53只双源核验通过，待复核0只，完整`manifest.json`已生成。共842011行，含1865行停牌估值；各股票按上市退市生命周期截断。所有当前资产校验和、交易日覆盖、内部一致性及来源标签复查通过，见[最后三股与完整仓库修复](final-three-warehouse-repair.md)。实时状态仍以网页“数据管理”或状态命令为准。

## 冻结的范围与历史成分

- 官方Tushare主源；沪深300采用官方接口的指数代码`399300.SZ`，基准行情使用`000300.SH`。
- 研究区间：2020-01-02至2026-10-30，截止请求时最新完整交易日。
- 预热要求：127个研究起点前交易日，数据起点2019-06-28。对应当前十因子的最长回看126日加一个信号日；更长窗口须另建更长预热计划。
- 已获取2019年12月至2026年10月共83期历史成分快照。研究区间内的历史并集493只，包括27只科创板股票；不是每天用493只作为候选池。
- 每个快照从其日期后的下一个交易日起使用，区间左闭右开；最新快照若在研究结束日之后才生效，不影响该区间的股票池。缺失月份、数量不完整、重复股票、权重和异常均拒绝规划，不用未来名单填补。
- `index_weight`是月度快照，不能证明精确公告可用时点，也不能复刻每次实际指数调整生效日。本阶段明确标为`monthly_snapshot_next_session`、`point_in_time_certified=false`。该口径可能滞后真实调仓，后续精确复刻需补充调整公告及生效日期。

[Tushare历史成分接口](https://tushare.pro/document/2?doc_id=96)明确提供月度成分与权重；这里保留完整原始快照，程序没有把月末名单回填到月初。

## 生命周期和预热

下载起点不早于股票上市日期，结束不晚于退市生效前的最后交易日；当前上市、退市和暂停上市资料均纳入参考，当前名称和行业只用于展示。

新上市股票无法拥有上市前数据，按实际可得历史标记`history_sessions_before`及`has_required_pre_history`，不会制造上市前行情或缩短因子窗口。停牌价格只允许在独立交易状态证据支持时沿用此前收盘估值，成交量为零。亏损等原因导致PE缺失不再被误认为伪造停牌价格；没有此前PE时不声称已沿用一个PE值，估值因子仍按缺失处理。

数据中保存逐日`index_member`；安全读取函数`index_observations_on`按查询日的历史快照读取，标明历史不足及上市退市边界排除，报价缺口仍报错。历史并集和未来成分不会直接成为过去的选股池。

## 下载管理与流控

官方主源采用共享SQLite账本：保守限制为每分钟120次、每个API每天90000次，低于当前2000积分通用档位。失败重试也计数，缓存命中不联网。

BaoStock拥有跨股票、跨缓存目录、跨本机同用户进程的独占连接锁。实际SDK请求在隔离子进程中顺序执行，登录、两种复权口径查询、翻页和退出均经统一消息钩子计数；不以返回的行情行数代替请求次数。自定预算为每日10000次、每分钟最多60次，并保持至少1秒消息间隔。账本保存在`data/network-control/quota.sqlite3`，按上海自然日累计，重启不会清零。

达到预算后保留断点并暂停；收到黑名单返回码后记录持久暂停，不自动继续探测；连接连续三只股票失败则暂停，避免持续重连。单次连接失败只有限重试，超时进程退出后才能打开下一连接。计数覆盖本项目适配器，其他程序共用IP的请求需要另行预留余量。数据源的实际规则仍优先于本地预算。

股票分开下载和发布，通过者保存归一化Parquet与校验报告；参考快照、原始响应、每股来源、文件校验和、校验代码指纹和执行进度均留存。续传只复用同源、同参数且校验和正确的缓存。修改校验代码会使运行任务暂停，避免同一批股票混用不同版本的校验逻辑。

## 网页和命令

更新后重启网页服务并刷新浏览器。在“数据管理”顶部可查看原始响应保存数、核验通过数、待复核股票及配额，点击“暂停下载”或“开始 / 续传”。暂停等待当前股票处理完，后台工作进程不依赖网页保持打开。重启网页服务不会主动终止该下载进程。

```powershell
# 准备参考数据和冻结计划：首次会联网，已有计划则核对后复用
.\.venv\Scripts\python.exe -m finance_quant.cli index-plan

# 前台运行/续传，或增加 --limit 3 做小范围验收
.\.venv\Scripts\python.exe -m finance_quant.cli index-download

# 查看简要状态与配额，不下载数据
.\.venv\Scripts\python.exe -m finance_quant.cli index-status
```

网页状态接口：`GET /api/v1/research/index-download`；开始续传和暂停为同源本机POST，分别为`/start`和`/pause`，只接受空JSON对象。读取状态不会创建下载任务。默认仓库为`data/warehouse/csi300-2020`。`PAUSE`文件表示在下一只股票前暂停，网页续传会清除此标志。

## 核验异常和可用范围

试验中发现BaoStock也有历史数据内部不一致：000001.SZ的2020-12-31，以及000002.SZ的2020-11-16、11-19、11-20和2025-01-09等记录，其后复权收益与自身涨跌幅不一致。重新查询2020年短区间仍出现问题，不能假定缩短区间就能修复。

后续逐股复核已确认这两只的前复权全区间序列内部一致，且与官方原价及收益一致，现保留官方序列通过核验；旧后复权错误证据继续保留。盐湖股份恢复上市首日、必康退退市整理首日的大幅涨跌经事前公告和两源逐日数据确认后，按精确日期审核并标记无日涨跌幅限制。天齐锂业前后复权均异常，仍隔离。具体日期、原因及修复边界见[待复核股票诊断](csi300-quarantine-review.md)。

官方原始响应、错误日期及第二来源校验和均留存，不覆盖异常捕获，不放宽通用异常阈值。网页分别展示“主源四类原始响应已保存”和“核验通过”，两者不可混用。

只有所有股票通过时才发布完整仓库`manifest.json`；未全通过时保留`progress.json`、逐股已验证资产和异常清单。续传复用旧捕获，若需要检验供应商修订，需显式创建新的第二源捕获版本，不能直接删除或覆盖证据。

此阶段完成数据归档和下载控制，尚未将动态历史池接入旧固定池回测入口，也未补齐科创板等执行规则。仓库使用独立schema并明确`ready_for_legacy_fixed_pool_research=false`，旧回测入口无法把493只历史并集直接当成固定股票池。历史PE等供应商修订/发布时间也未获得独立PIT认证。
