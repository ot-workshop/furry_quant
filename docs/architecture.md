# 系统架构

Compose 运行三个长期服务：PostgreSQL 保存市场事实、任务、修订和结果摘要；FastAPI 提供同源网页及任务查询；单 worker 顺序执行下载和研究任务。Alembic 是启动前的一次性迁移，不是常驻服务。API 不在自身进程中运行 Qlib。

市场行情、复权、估值、交易状态、历史成分、行业和基准在 PostgreSQL 中各有明确表。更新先保存并校验供应商响应，再用短事务发布当前值、来源和字段修订。空响应不代表删除；来源改变必须显式核验。常规更新重查近期交易日，复权尺度或价格来源变化会触发完整已存历史复核。

研究输入有两种固化方式：数据库事实可在 `REPEATABLE READ` 事务内物化；已发布的行情快照按 manifest 和文件哈希登记为内容寻址数据集。仍会增量变化的历史成分仓会先把该 manifest 声明的参考文件和股票资产硬链接到 `datasets/<content-id>`，跨文件系统时才复制。Qlib 只读取冻结输入，不在逐日循环查询数据库。

净值、成交、费用和指标写入 PostgreSQL；完整持仓和大型因子明细写入 Parquet。每个因子、回测和评估结果通过 `research_run.dataset_id` 关联同一输入数据集，数据库同时登记文件相对路径、行数和哈希。备份从这些外键和文件登记生成清单，所以旧运行不会因当前数据修订而改变，也不会只备份结果却遗漏输入。

任务队列使用 PostgreSQL 行锁领取，并用会话级 advisory lock 保证只有一个有效 worker。API 可继续响应和排队；浏览器断开不影响 worker。第二个 worker 无法取得锁时会退出。

前端使用 React、Ant Design 和 ECharts。回测详情采用可折叠总导航、详情左侧导航、宽图表和按日抽屉；URL 保存运行、标签和日期。浅色、深色、跟随系统以及红涨绿跌偏好共用一套颜色令牌，切换主题时保留图表缩放和图例状态。
