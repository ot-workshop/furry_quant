# 申万行业数据

行业数据用于历史行业中性化和组合行业暴露诊断。系统保存申万一级、二级、三级分类的**历史成员区间**，并保证版本不可变、研究可复现。

## 数据来源

| 接口 | 用途 | 积分 | 说明 |
| --- | --- | --- | --- |
| `index_classify` | 申万分类目录 | 2000 | SW2014 / SW2021；含 `level`、`industry_code`、`parent_code` |
| `index_member` | SW2014 成员 | 2000 | 按 `index_code` 查询；`is_new=Y` 实测返回空，历史记录在 `N`/不传时返回 |
| `index_member_all` | SW2021 成员 | 2000 | 按 `l1_code`/`l2_code`/`l3_code` 查询，`is_new=Y/N`，单次最多 2000 行 |

- SW2014：28 个一级、104 个二级、227 个三级。
- SW2021：31 个一级、134 个二级、346 个三级。
- 全量下载约 1,700 次请求，按 120 次/分钟约 15 分钟；共用 Tushare 每日额度。
- 单板块响应达到 2000 行时视为可能截断，直接拒绝发布，不保存不完整版本。

## 存储与版本

```
STORAGE_ROOT/data/industries/official-tushare/
  <内容哈希>/intervals.parquet   股票-行业-级别-纳入/剔除区间
  <内容哈希>/sectors.parquet     分类目录（代码、名称、级别、父级）
  <内容哈希>/manifest.json       文件哈希、级别汇总、核验日期、政策
  current.json                   当前版本
  raw/                           请求缓存，可断点续传
  jobs/<计划号>/                 预览计划与下载进度
  PAUSE、download.lock
```

- `intervals.parquet` 字段：`instrument, classification, level, industry_code, industry_name, parent_code, in_date, out_date`。
- 版本号只由区间和目录内容、schema、政策哈希生成；重复下载相同数据不会产生新版本。
- 旧的 `sw-l1-history-v1` 版本仍可读取，并自动视为只有一级行业；已有研究结果和指纹不变。
- `data_asof` 记录本次下载日期，只用于“核验截止”检查，不参与版本号。

## 时点规则

- SW2014 只用于其有效研究区间；SW2021 最早从 2021-12-13 起使用。
- 纳入/剔除记录从记录日期的**下一交易日**起生效；`in_date` 当天不提前使用。
- 不回填当前行业；缺失和冲突单列，不用当前标签前向/后向填充。
- 结果标记 `point_in_time_certified=false`：供应商只提供事后日期，实际公告和修订时间未认证。

## 下载

1. 数据管理 → 行业数据。
2. 勾选级别（默认一级、二级、三级），选择是否刷新缓存，点击“预览下载”。
3. 确认级别、板块数、预计请求和耗时后开始下载。
4. 可暂停、续传；全部板块成功才发布新版本，失败时旧版本继续可用。

## 行业中性化

“新建研究 → 因子配置 → 行业中性化”选择级别：

- 一级（默认）：旧行为，请求不写 `industry_level`，旧结果与指纹保持兼容。
- 二级/三级：请求写入 `industry_level`，进入结果指纹；研究绑定当前行业版本。

行业版本必须包含所选级别，否则提交被拒绝并提示重新下载或切换级别。行业中性化只去除因子值的行业均值，不约束最终持仓的行业权重；持仓行业上限需要另行实现组合约束。

## 已知限制

- 申万2014/2021切换是保守的日期约定，不是公告生效日认证。
- 供应商历史记录可能滞后或缺少旧区间；缺失不会用当前分类补偿。
- 行业分类变化频繁，二级/三级行业在长区间内可能出现成分和代码变化，研究结果需结合版本日期解释。
