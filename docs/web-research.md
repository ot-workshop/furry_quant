# 网页自定义研究与后台任务

日期：2026-10-31。最新的参数生效、异步跳转与历史日期复核见[网页流程复核](web-workflow-review.md)。

网页新增“新建研究”，支持配置股票池、已有因子、窗口和权重后提交后台计算。结果继续由现有 Qlib 工作流生成，按任务绑定具体评分、回测和因子评估批次。

## 使用流程

```powershell
npm.cmd --prefix frontend run build
.\start.ps1
```

打开 <http://127.0.0.1:8000>，首页即为“新建研究”。

1. 填写研究名称。选择“使用已有数据”，选一个已通过校验的快照，勾选股票；或选择“下载新股票池”，填写代码和基准。新任务默认按回测日期自动计算数据区间，不需要手填数据起止日期。
2. 从[10项指标](factor-library.md)中勾选所需项，默认仍为动量、盈利收益率、低波动三项。带窗口项接受2至252个交易日，可配置剔除天数、成交额基准窗口及同类多窗口实例；启用实例权重须合计100%，可使用“等权分配”。
3. 设置回测日期、目标持股数量和初始资金。在“高级设置”调整仓位、费用、换仓数量和诊断参数。
4. 自动日期下载模式点击“预览下载方案”，查看预热起止、实际回测日、完整下载区间和股票/因子参数，再点击“确认下载并运行”。预览只查询交易日历，不下载行情或创建任务。已有快照或手动日期模式直接点击“创建研究任务”。任务列表显示排队、下载（如需要）、准备数据、计算因子、Qlib回测、因子评估等阶段。
5. 任务成功后点击“查看评分”“查看回测”“查看因子评估”，打开该任务的具体结果。股票评分页还可查看原始值、公式、参数、贡献、覆盖和缺失原因。旧任务可以“再用此配置”或下载配置记录。

数据日期与回测日期不同：回测前必须保留足够历史用于滚动窗口及前一天评分。回测起止日必须是实际交易日。诊断持有期用于 IC/分组收益分析，不会把策略改成固定持有若干天后卖出。

下载模式与已有快照模式都会检查窗口预热。网页显示所需/可用历史及已知最早起点，可点按钮明确调整；例如2025年1月开始的数据启用126日中期动量，最早从2025-07-15回测。已下载但后续失败的数据可点击“再用此配置”后“改用已有快照（免下载）”，窗口和权重保留。具体规则与实际失败恢复验收见[预热校验](warmup-validation.md)。

自动日期按最长因子回看加一个信号日，使用实际交易日历倒推；预热结束于实际回测开始前一个交易日，行情结束于实际回测结束日。休市起点顺延、终点前移，均在确认时展示。股票池、日期、因子、窗口、权重或资金费用等任何草稿变更都会使旧确认失效，必须重新预览。重试提交复用幂等标识，不会因响应丢失重复创建同一任务。

需要固定下载区间时，取消“按回测日期与因子窗口自动计算下载区间”。手动模式保留“计算日期调整方案”，可选择补足历史或延后回测；“再用此配置”默认恢复原任务的固定数据区间，可主动勾选自动推算。

已有数据模式完全离线；下载模式沿用后端本地配置的 Tushare 服务及 BaoStock 校验规则。单次最多50只股票，同时排队与运行的任务最多20个。未做过有效校验的数据不会出现在快照选项中。

仅选择部分股票时，会生成独立的股票池快照，重新计算该池的百分位评分，不会直接截取原池的分数。派生快照保留父版本、校验和及逐股来源，原快照与默认研究配置保持不变。

少于3只有效股票时，IC统计可能不可用；窗口过长、估值缺失、持股数量过大或区间太短会显示校验错误。任务失败不会伪装成零收益或成功结果。

## 保存、队列和重启

- 浏览器自动保存表单草稿；已提交配置随任务持久保存。“下载 JSON 配置”导出的是网页任务请求记录，不能直接当作旧 CLI 的 `--config` 文件。
- `runs/tasks/catalog.sqlite3` 保存请求、执行阶段、状态、错误和结果引用；任务接口不暴露内部执行路径或凭据，结果仍保留既有本地数据来源信息。
- 单个调度器按提交顺序处理任务，每个任务在独立 Python 子进程中运行 Qlib，避免阻塞 HTTP 服务或混用 Qlib 全局状态。
- 重复提交同一个请求标识只创建一次任务；相同数据、因子和交易参数的计算继续复用已有不可变产物。
- 排队任务支持取消。运行中的任务目前不提供取消按钮；关闭服务会中断正在运行的任务，重启后标为“已中断”，可使用原配置重新运行。排队任务保留并在重启后继续调度。
- 同一结果目录只允许一个网页服务拥有调度器。其他服务仍可查询结果，但不能另开并行队列。
- 进度表示已完成的阶段数量，没有虚构逐笔计算百分比。前端在有活动任务时自动轮询，刷新页面仍可查看任务记录。

## 接口

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/api/v1/research/options` | 有效快照、股票列表、因子定义与默认参数 |
| GET | `/api/v1/research/tasks` | 最近100个任务及总数 |
| GET | `/api/v1/research/tasks/{id}` | 任务详情与结果引用 |
| POST | `/api/v1/research/tasks` | 提交配置，使用 `Idempotency-Key` 防止重复创建 |
| POST | `/api/v1/research/tasks/{id}/cancel` | 取消仍在排队的任务 |

提交接口只接受本机工作台来源的 JSON，客户端不能传入任意目录、执行代码或数据服务凭据。生产服务仍只绑定 `127.0.0.1`。Vite开发端口5173的本机来源也受支持。

## 验收与限制

后端测试覆盖参数边界、严格JSON、请求来源、股票池派生、联合数据来源保留、请求防重、排队取消、单队列互斥、重启恢复、真实后台子进程，以及结果与评分批次绑定。前端测试覆盖百分比单位转换、股票格式归一、权重总和、窗口/费用/诊断限制与草稿恢复。

最终全量335项Python测试及13项前端参数/组件交互测试通过，TypeScript/Vite生产构建通过。仍有既有依赖弃用提示和前端包体积提示。

实际联合快照验收任务：三只银行股、10日动量60%与20日低波动40%，初始资金15万元、持有2只、80%目标股票仓位，回测2026-03-02至2026-09-30。已生成147个交易日、44笔成交的结果，现金与市值逐日对账及费用合计通过；同配置再次运行复用结果。该案例用于功能验收，不是投资建议或策略有效性证明。

新股票池的下载编排使用离线供应商测试完成验证；本轮实际任务使用已有联合快照，没有重新向付费服务下载新股票。

浏览器自动验收因工具无法可靠识别当前浏览器URL而被停止，未完成视觉布局和点击流程的自动验收；TypeScript、生产构建及实际任务/接口验证已完成。没有将接口通过描述为视觉验收通过。

当前可配置三个已有因子及一种Qlib策略，暂不支持网页编写新因子公式、上传执行代码、网页历史分段实验配置、运行中强制取消或自动定时更新。独立核验确认的整日停牌已支持前收估值、禁止买卖和评估标签排除；未知缺数仍报错。原有财报时点、历史股票池、退市、盘中停牌和交易容量等限制继续存在。

当前股票池支持沪深主板及创业板A股；科创板、北交所、B股、ETF和指数尚未适配完整数据或交易规则，前后端均会提前拒绝。扩大或重组股票池会按股票/日期/供应商及校验哈希复用历史下载分片，不会因为仅更换池子就重下全部共用行情。服务提供上市/退市日期时，数据区间包含上市前/退市后交易日将明确失败，不能通过填充制造完整历史。见[多股票池复核](pool-workflow-review.md)。

失败任务显示具体股票、接口、日期和分类，可展开“查看失败明细”。错误内容来自结构化下载报告，不直接暴露供应商响应或凭证。修复代码后，旧失败记录保留原状态，可复用配置重新运行；后台服务与前端资源需重启/刷新后加载新增展示。
