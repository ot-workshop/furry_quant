# 回测差异对照（首版）

页面上选两份**已完成**的回测：A 为对照，B 为候选。页面与接口只读取已存结果，**不重跑、不修改**
原结果；首版也不定位“最早评分差异”或“最早成交差异”。

- 入口：侧栏「研究 → 差异对照」（`/compare`），或直接访问 `/api/v1/backtest-comparisons`。
- 接口：`GET /api/v1/backtest-comparisons?baseline_run_id=<A>&candidate_run_id=<B>`，
  没有批次返回 404，同一批次返回 422，结果文件损坏返回 409。

## 怎么读

1. **先看结论行。** 只有冻结证据支持时才会写“同一执行结果，只有评价基准不同”；多项变化或证据不足
   时写“发现多项差异”或“证据不足，无法判断原因”，不会把相关性写成原因。
2. **再看核心结果。** 策略总收益、基准收益、收益差（超额收益）；差值为 **B − A**，收益类用
   **百分点**。区间或绩效口径版本缺失或对不上时保留 A/B 原值，差值为空并标“不可比”，不输出数值。
3. **最后看版本与参数证据。** 按行情与冻结数据集、财务、行业、代码与运行环境、因子与参数、
   交易规则、评价基准分组；每行给 A、B 和状态：
   - **相同**：两侧都有记录且逐项一致；
   - **不同**：两侧都有记录但值不同；
   - **未知**：至少一侧没有记录。未知不是相同，也不显示成 0。

## 同执行、只换基准时的那句解释

执行指针可支持同源关系。只有区间与绩效版本已知且可比、总收益及超额算式经核对一致、计算或交易
证据无冲突时，才解释已存基准收益变化对应的报表超额差；这不是策略变化的因果证明。旧基准序列
版本缺失仍标未知，避免写成“只有评价基准不同”。所有差值统一 B − A，交换后方向随之反转。

## 边界

- 首版不扫描全量净值与成交明细，因此不给出“最早差异出现在哪一天/哪一笔”。
- 旧结果未保存来源版本时，相关条目保持“未知”；旧价格基准的序列版本同样。
- PostgreSQL 读取所选结果的摘要、元数据、冻结绑定及绩效版本；固定池仅按冻结 ID 补相应因子
  元数据，不加载净值、成交或 Parquet 明细。文件存储会完整解析结果 JSON 后取所需字段，因此
  较大 JSON 仍有读取和内存成本；不重跑或改写原结果。
- “总收益一致”指两侧数值在 1e-12 浮点容差内相等；展示的差值保留原始精度，不靠四舍五入判断。
