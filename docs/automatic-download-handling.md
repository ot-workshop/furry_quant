# 自动下载处理与可读报告

本功能用于沪深300历史数据仓的正式下载流程。停牌处理等规则已经进入生产代码，不依赖`.agent-work`下的临时排查脚本，也不是按三只股票写死。

## 自动处理顺序

| 触发情况 | 程序采取的措施 | 报告如何说明 |
| --- | --- | --- |
| 报价缺失或无成交疑点 | 查询该月份官方每日停复牌；只接受明确全天停牌、日期/代码正确且与成交不冲突的记录 | 涉及日期、官方请求和证据校验和、此前收盘估值及零成交处理 |
| 盘中停牌 | 保留当天真实价格、成交量和成交额 | 明确“盘中停牌保留真实成交”，仅在已保存行情确有成交时这样描述 |
| 官方状态同日S/R等歧义 | 保留官方冲突记录，使用覆盖完整日历且两种口径一致的独立交易状态 | 官方冲突日期及切换证据的处理，不把状态核验升级为价格核验 |
| BaoStock复权口径内部异常 | 最多切换另一口径，完整区间重新核验；失败捕获不覆盖 | 原失败日期、所选口径、整段重新核验说明 |
| 抽样辅助来源不可用 | 官方自检通过时保留单源；主源本身未通过则继续阻断 | 明确保留了哪种等级和未完成什么检查 |
| 主源价格/复权异常且辅助完整有效 | 整个股票区间使用辅助行情与相对因子，估值/涨跌停仍用官方 | 整段回退的范围和来源分工 |
| 已审核的大幅交易事件 | 核对事前公开证据及收益一致性，保留真实涨跌和无日涨跌幅限制标记 | 日期、公告链接及已知日期 |
| PE缺失或非正 | 保留真实值及缺失，不编造正PE | 作为因子可用性提示展示，不把它写成已修好的数据 |
| 证据不足、未知大幅涨跌、有效来源明确冲突 | 保留原始捕获，当前股票不发布；其他股票可继续 | 单独列为“待复核，未发布”，给出原因和所需下一步 |
| 限额或访问限制 | 成功缓存持久保存，需要该来源的操作暂停 | 显示已暂停及续传说明，不绕过访问限制 |

这些规则不保证供应商将来所有新异常都能自动修正。未知公司行动需要新的可靠依据，不能自动套用旧公告。日配额/访问限制解除后可续传，当前未实现跨日自动重启或供应商修订的自动探测。

## 网页使用

“数据管理”→“沪深300历史数据下载”→“查看自动处理报告”。

- 摘要显示通过、自动处理/说明限制、待复核及待处理数量。
- 默认显示自动处理与待复核股票；可按代码/名称搜索，切换“全部股票”查看普通检查及PE可用性提示。
- 每只股票可展开“发现”“处理”“涉及日期”和“查看依据”；单源、双源和补缺等级保持区分。
- 提供完整JSON下载。报告对应明确进度时点，进度变化时提示刷新，不将旧报告伪装成新结果。
- 读取报告不发起行情下载，也不改写已发布行情。

报告是诊断视图，不会把当前冻结计划自动延长到最新日期。“开始/续传”仍复用同源、同参数且校验和正确的缓存；若要新日期范围，应另建计划。固定池研究任务的旧下载入口不在此报告范围内。

## 自动保存和本地位置

网页后台使用的`index-download`命令在成功、部分完成、暂停和中断退出时自动生成报告；进行中点击查看会按当时进度生成/复用报告。报告生成失败不覆盖原下载结果，可重试读取。

- 当前报告：`data/warehouse/csi300-2020/handling-report.json`
- 分任务报告：`data/warehouse/csi300-2020/handling-reports/<job_id>.json`
- 可读API：`GET /api/v1/research/index-download/report`
- 下载API：`GET /api/v1/research/index-download/report/download`

报告来源于每股已有核验收据，记录进度版本、数据等级、处理规则、日期和证据。报告代码与行情校验指纹分离，增加解释功能无需重写已完成的493只数据。

## 验证

514项全量后端、38项前端测试和构建通过；真实React事件连接本地API读取493只报告、筛选凯赛/广汽/容百、验证盘中成交与状态歧义说明、下载JSON，无POST操作。联测中禁止调用主辅行情接口，确认查看报告不下载数据；现有仓库校验版本保持一致。

真实数据报告覆盖493只、440只单源和53只双源，其中132只存在自动处理或限制说明；PE可用性另作为信息记录。报告输出不等同于新增双源认证。

证据：`.agent-work/handling-report-full-tests.log`、`handling-report-frontend.log`、`handling-report-build.log`、`handling-report-live.json`。
