# 十项日频因子与网页配置

本阶段将因子公式、参数、方向、输入字段及缺失规则集中登记在 `research/factor_library.py`，配置校验、计算、网页选项和结果明细使用同一份定义。Qlib继续负责交易执行和IC计算。默认仍启用原有三项，新增指标按需勾选；历史结果不会被改写。

下载模式的窗口预热前置检查、最早起点按钮及免下载复用已补齐，截图任务的原因与恢复步骤见[预热校验](warmup-validation.md)。

## 指标口径

`P` 为按各股首日归一的累计复权收盘价，`r` 为复权日收益。窗口均按交易所交易日推进，停牌不压缩日历。年化使用252日，标准差使用样本标准差。

| 名称 / 配置名 | 默认参数（交易日） | 原始值 | 评分偏好 |
| --- | --- | --- | --- |
| 动量 `momentum` | window=20，skip=0 | P[t-skip] / P[t-window] - 1 | 越高越好 |
| 盈利收益率 `value` | 无窗口 | 1 / 正PE_TTM | 越高越好 |
| 波动率 `volatility` | window=10 | 完整窗口内r的标准差 × √252 | 越低越好 |
| 账面价值收益率 `book_to_price` | 无窗口 | 1 / 正PB | 越高越好 |
| 小市值 `size` | 无窗口 | -ln(总市值/CNY) | 越高越好 |
| 短期反转 `reversal` | window=21，skip=1 | -(P[t-skip] / P[t-window] - 1) | 越高越好 |
| 中期动量 `medium_momentum` | window=126，skip=21 | P[t-skip] / P[t-window] - 1 | 越高越好 |
| 下行波动率 `downside_volatility` | window=20 | 完整窗口内负r的标准差 × √252；至少2个负收益 | 越低越好 |
| 滚动最大回撤 `max_drawdown` | window=60 | window+1个价格点中，min(P / 历史累计最高P - 1) | 越高越好（越接近0） |
| 成交额异动 `amount_anomaly` | window=20，baseline_window=60 | 最近20日平均成交额 / 此前不重叠60日平均成交额 | 越高越好 |

动量类的window是总跨度。例如126/21使用t-126至t-21的收益，并非再向前增加21天。下行波动率采用负收益条件样本标准差，不等同于以0为目标的半标准差。成交额两段均须至少80%的日期有正成交额、当日有成交、基准均额为正；负数、缺失或非有限成交额会使所在窗口失效。

window与baseline_window各接受2–252的整数；skip接受0至window-1。PE、PB、市值不接受窗口。所需字段在网页卡片和结果公式中展示；PB、总市值沿用已下载的daily_basic字段，无需新增财报下载。

## 网页操作

1. 在“新建研究”选择数据快照与股票池，也可下载新股票池。
2. 勾选指标，修改窗口、剔除天数或成交额基准窗口，并设置合计100%的正权重。“等权分配”按已启用实例分配。
3. 动量等带窗口的指标可点击“添加同类不同窗口”，例如同时启用20日动量和60日动量。每个实例有独立参数、权重和结果列，最多20个实例。
4. 确认回测起点具有足够历史，提交任务。原始评分最早位于回看跨度对应日期，回测最早在下一交易日成交。成交额需要window+baseline_window个数据日。
5. 任务完成后点“查看评分”，在股票页“计算明细与数据覆盖”查看原始值、百分位、权重、综合分贡献、公式、字段、覆盖数及排除原因。“查看回测”和“查看因子评估”打开该任务绑定的批次。

配置复用和草稿会保留新增指标及同类多窗口实例。未获得综合分的股票仍在选择器中，明细展示已有原始值和缺失原因。两只股票可以评分和回测；IC最小样本仍为3，两股任务的IC显示缺失及原因，不伪造统计。

## 评分、缺失与时间边界

先计算每个原始指标，再对当日所有入选指标均有效的股票交集排名。平均秩百分位乘100，分项贡献为百分位乘权重，贡献之和为综合分。至少2只共同有效股票才评分。新增指标缺失时不补零、不自动删因子、不重新分配权重。

每个日期保存全股票池、交集有效数及每项有效数；被排除股票保存原始值和原因。输入股票池必须有完整的共同交易日日历，缺日拒绝计算，避免滚动窗口悄悄缩短。长期单边上涨且负收益不足2次时，下行波动率缺失，不当作0风险。

提交任务前会逐日检查有效股票数。若共同有效数不足目标持股数（最低2只），请求直接拒绝并显示日期、交集数量及缺失指标数量，不创建一个注定失败的任务。例如连续停牌后，即使价格已经恢复，成交额窗口仍可能暂时达不到80%有效日要求；可按公式调整窗口、股票池或回测起点，不补造停牌成交额。

计算只使用当日与此前行情，不使用后续收益标签，不反向填充。T日18:00假设可用的信号只供下一交易日开盘。原有PE沿用已经核验的停牌前可得值，并记录valuation_asof；新增PB和市值在停牌沿用日排除。账户估值、停牌禁买卖和评估标签规则继续使用原实现。

**供应商PE/PB/市值的历史发布时间和修订仍未独立认证。程序因果性测试不能证明第三方数据满足完整时点要求。**本阶段没有接入真实财报因子、行业/市值中性化、动态权重或机器学习训练；固定股票池仍需考虑幸存者偏差。

## CLI与扩展

现有配置的factors字段也支持独立实例，例如：

```json
{
  "factors": [
    {"name": "momentum", "id": "fast", "weight": 0.3, "window": 20},
    {"name": "momentum", "id": "slow", "weight": 0.3, "window": 60, "skip": 5},
    {"name": "book_to_price", "weight": 0.2},
    {"name": "amount_anomaly", "weight": 0.2, "window": 20, "baseline_window": 60}
  ]
}
```

这是局部配置示例，仍需data、backtest等现有字段。id可省略；同类重复实例必须提供不同id。id限小写字母开头的字母、数字、下划线，不允许占用结果字段或其他指标名。每个启用实例权重须大于0，合计1。

添加未来指标时，在因子库登记定义与计算器，补充独立公式及时间边界测试；网页从后端读取参数定义。当前参数类型为窗口、剔除和基准窗口；引入其他参数类型时仍需扩展统一配置协议。未提供任意Python代码执行入口。

数据版本、实例、参数、权重和因子源码共同决定评分ID。改资金/费率或回测区间可以复用同一评分；改股票池/因子参数会产生独立评分。结果JSON保存绑定定义，旧文件继续按旧口径展示。

## 验证方式

2026-10-31：全量411项Python测试、22项前端测试、TypeScript检查及Vite生产构建通过。新因子专项25项包含在全量测试中；构建仍有原有的大包提示，Qlib及数值依赖仍有兼容性/弃用提示。

专项测试使用2/7/17/50股不同生成股票池，独立标量公式核对十项原始值、百分位和贡献，并通过模拟下载、任务队列、原生Qlib和评估完整流程。未来数据扰动覆盖价格、复权、PE、PB、市值、成交额；截断重放确认历史结果不变。

真实快照验收完成9组成功任务及1组预期前置拒绝：15股基准、仅改权重、仅改动量窗口、仅改中期动量剔除天数、仅改成交额基准窗口、缩为5股、5股添加第二个动量实例、缩为2股，以及覆盖2025年夏季停牌的15股区间。逐个打开对应评分、回测和评估，并在末尾重新打开最早和最新任务。两股池9月初因长期停牌后的成交额覆盖不足被拒绝，明确显示指标及1/2覆盖，不创建任务；只延后起点至9月15日后成功。

最终独立复算通过302,940个原始因子值、636,025次评分/贡献/综合分校验、2,150个账户日、1,799笔成交和69,698条收益标签。仅改权重时原始值完全不变，4,328条综合分改变；改动量窗口、中期剔除、成交额基准分别改变4,437、4,435、4,414条对应原始值，缩池改变1,490条共有观察的分数。这些变更也传递到了实际回测净值。停牌区间任务复用相同评分批次、保存独立回测/评估批次；停牌禁成交、辅助值排除及现金/持仓估值核对通过。

记录为 `.agent-work/ten-factors-live/evidence.json`（任务及网页请求）、`audit.json`（独立计数）和隔离runs目录。用户当前五股快照 `joint-157dbae708578dd6` 与活动配置保留。

真实冻结快照的独立验收脚本为 `scripts/check_factor_library_workflow.py`。它从落盘数据重新计算原始指标、秩、贡献、成交费用、账户账目及下一交易日收益标签，不调用生产计算器。实际React事件通过本机HTTP连接隔离队列，检查配置提交和对应结果跳转；图表在DOM测试中使用替身，因此不代表浏览器视觉验收。任务与审计产物位于被忽略的 `.agent-work/ten-factors-live/`，不更改用户活动配置，不调用付费接口。

本轮因子验收曾通过QA环境开关绕过本机Python的WMI平台信息查询。后续日常启动排查复现了相同阻塞，已将Windows Python 3.12的进程内兼容处理接入正式CLI和任务入口，并使用无QA开关的真实PowerShell启动及后台任务验证。当前用法见[启动说明](startup.md)；未改系统或第三方库文件。
